Title: Show each visit's status on the owner detail page

Story: As a clinic receptionist, I want to see the status of every visit on the owner's page, so that I can tell at a glance which visits are scheduled, done or cancelled.

**Requires a new or changed contract from:** petclinic-rest-api

Expected behaviour:
- The backend now returns a `status` on every visit (story PC-101). Its allowed values are defined by the `VisitStatus` enum in the attached `openapi.yml`: `SCHEDULED`, `COMPLETED`, `CANCELLED`. Use only these values; do not add others.
- The owner detail page (`/owners/{id}`) lists each pet with its visits (`app-pet-list` → `app-visit-list`). Add a **Status** column to that visit table, between **Description** and **Actions**.
- Show a readable label, not the raw value: `SCHEDULED` → "Scheduled", `COMPLETED` → "Completed", `CANCELLED` → "Cancelled".
- When a visit has no `status` (an older backend, or the field is missing or null), show "Not set". When it has a value outside the three above, show the raw value as it came. The page must never fail to render because of the status.
- The visits come nested in the owner response (`GET /api/owners/{ownerId}` → `pets[].visits[]`); no new API call is needed.

Acceptance criteria:
- AC1: The `Visit` model has an optional `status` typed with exactly the three values from the attached contract (`'SCHEDULED' | 'COMPLETED' | 'CANCELLED'`), defined once and reused, not repeated as string literals across components.
- AC2: On the owner detail page, every visit row shows a Status column, placed between Description and Actions, with the header "Status".
- AC3: A visit with `status: "SCHEDULED"` shows "Scheduled"; `"COMPLETED"` shows "Completed"; `"CANCELLED"` shows "Cancelled".
- AC4: A visit with no `status` (field missing or null) shows "Not set"; a visit with an unexpected value (e.g. `"DONE"`) shows that value unchanged. Neither causes an error in the browser console.
- AC5: Visit dates, descriptions and the Edit Visit / Delete Visit buttons behave exactly as before.
- AC6: `npm install … && npx ng build --configuration development` passes.
- AC7 (CL-1): A `status` that is an empty string or only spaces is treated as missing and shows "Not set".

In scope:
- `src/app/visits/visit.ts` (status type and field).
- `src/app/visits/visit-list/visit-list.component.ts` and `.html` (Status column and label mapping). A small shared helper or pipe under `src/app/visits/` is fine if it keeps the mapping in one place.

Out of scope: setting or editing the status (the add-visit and edit-visit forms stay as they are), the visits list on any other page, styling beyond a plain table cell, NgRx (this app has no store), backend changes, unit tests (this repo runs build-only).

Attachments:
- `stories/PC-102/openapi.yml` — petclinic-rest-api's OpenAPI file after PC-101, copied as it is (from its `harness-metrics` branch, `contracts/PC-101/files/src/main/resources/openapi.yml`). Defines `VisitStatus` and the `status` property on `VisitFields` / `Visit`.
